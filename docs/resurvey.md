# 补测工单 v1

本文档是 [多视图点重建契约](contract.md)、[离线标定更正与点云交付](delivery.md) 与 [复测位移验收](acceptance.md) 的增量：在交付视图之上增加一个离线生成补测工单的子命令。原有 `camera-tracks --source ... --output ...` 与 `build/correct/query/export/apply/view/accept` 的输入、输出与退出码完全不变。

```
camera-tracks resurvey --view VIEW.json --plan PLAN.json --output REPORT.json
```

测量队在交付点云上规划下一轮补测：一份现有 `view` 导出的完整点表加一份区域方案，产出机器可读的补测工单与精确派单范围，供现场工具直接加载。命令只读输入：不回写点表、方案或任何状态库。成功时向标准输出打印一行 JSON 摘要并退出 0；任何输入错误打印 `error: <可读诊断>` 到标准错误、退出 2，此时不创建报告。报告始终以"同目录临时文件 + 原子新建"创建，**已存在的报告路径一律拒绝覆盖**；输出路径不得指向任一输入文件。运行依赖仅 Python 3.11+ 标准库，无网络。

## 1. 输入：view 导出与区域方案

点表输入必须是现有 `view` 命令导出的完整 JSON（`kind: "camera-tracks-view"`）。命令重新校验结构、点身份 `(sequence, track_id)`、精确有理数坐标，并按交付契约规范化编码重算点表指纹——篡改任何点值而保留旧指纹会被拒绝。随后逐项核对方案指定的 `dataset_id`、`version`、`fingerprint`：**三者都须匹配**；指纹相同也不能拿另一个版本的文件替用。

区域方案（UTF-8 JSON，一次只处理一个区域）：

```json
{
  "schema_version": 1,
  "kind": "camera-tracks-resurvey-plan",
  "zone_id": "zone-196-yard",
  "view": {"dataset_id": "survey-196", "version": 0, "fingerprint": "…"},
  "grid": {"x0": "0", "y0": "0", "cell_size": "1", "columns": 4, "rows": 4},
  "z_min": "0",
  "z_max": "10",
  "required_sequences": 3,
  "pass_rectangles": [[3, 0, 4, 1]],
  "forbidden_rectangles": [[0, 3, 1, 4]]
}
```

- `zone_id`：区域 ID（1..64 个 `[A-Za-z0-9_:-]`）。
- `view`：预期点表端点 `dataset_id`、`version`、`fingerprint`。
- `grid`：网格定义。`x0`、`y0`、`cell_size` 为仓库契约的有界十进制字符串，`cell_size > 0`；`columns`、`rows` 为 1..10^9 的整数。格子以 `(列,行)` 标识、从零开始；第 c 列对应 XY 区间 `[x0+c*s, x0+(c+1)*s)`（左闭右开），第 r 行同理。
- `z_min` / `z_max`：有效高程带 `[z_min, z_max)`，有界十进制字符串，`z_min < z_max`。
- `required_sequences`：每格要求的独立采集批数，1..100 的整数。
- `pass_rectangles` / `forbidden_rectangles`：免测通行矩形与禁入矩形两个列表，允许为空、相交与重复，**两类合计最多 25,000 个**。每个矩形是四个整数 `[左,下,右,上]`，覆盖格子 `[左,右)×[下,上)`，须非空且整个在网格内（`0 <= 左 < 右 <= columns`，`0 <= 下 < 上 <= rows`）。

格子归属与高程判定全部用精确有理数（`Fraction`）计算，不使用浮点近似：点 `(x,y,z)` 属于第 `floor((x-x0)/s)` 列、第 `floor((y-y0)/s)` 行，高程有效当且仅当 `z_min <= z < z_max`。

## 2. 格子分类

每格按以下顺序判定，四类互斥：

1. **禁入**：命中任一禁入矩形即为禁入，哪怕同时被声明为通行或已经有足够点。
2. **通行**：其余命中免测通行矩形的是通行格，不要求覆盖，也不因点数改变。
3. **已验收**：其余格子中，只用落在本格且高程有效的点，按点的 `sequence` 去重（不按 track 数）；独立批数达到 `required_sequences` 的格子为已验收。
4. **待补**：其余格子，包括没有点的格子。网格外的点不提供覆盖证据。

## 3. 派单连通

待补格和通行格都能参与派单连通；只能沿格边走，角接触不算。禁入与已验收格均不参与本轮派单连通，其所在区域不允许把两个缺测面并成一单。每个至少含一个待补格的连通分量生成一张工单；仅含通行格的分量不出单。同一工单内的待补范围本身可以因免测通道而分成多块。零工单是正常结果（退出 0，`orders: []`）。

工单计量和施工范围都只包含待补格：不用分量外接框替代范围，也不把通行格算成补测面积。

## 4. 报告

报告关联区域、端点与网格定义，并回显高程带与所需批数：

```json
{
  "schema_version": 1,
  "kind": "camera-tracks-resurvey-report",
  "zone_id": "zone-196-yard",
  "view": {"dataset_id": "survey-196", "version": 0, "fingerprint": "…"},
  "grid": {"x0": "0", "y0": "0", "cell_size": "1", "columns": 4, "rows": 4},
  "z_min": "0", "z_max": "10",
  "required_sequences": 3,
  "cells": {"accepted": "1", "pending": "13", "passage": "1",
            "forbidden": "1", "total": "16"},
  "orders": [
    {"identity": [0, 0],
     "pending_cells": "13",
     "bounding_box": [0, 0, 4, 4],
     "rectangles": [[0, 0, 1, 3], [1, 0, 2, 4], [2, 0, 3, 1], [3, 1, 4, 4], [2, 2, 3, 4]]}
  ]
}
```

- `cells`：四类精确格数与网格总面积，**十进制整数字符串**（可超过 2^53，避免现场前端读错），四类之和等于 `total`。
- `orders`：按标识顺序排列。每单给出：
  - `identity`：标识该单的最小待补格（先比较行，再比较列），按 `[列,行]` 输出；
  - `pending_cells`：本单待补格个数，十进制整数字符串；
  - `bounding_box`：待补格的最小外接格边界 `[左,下,右,上]`（半开）；
  - `rectangles`：待补范围，编码为若干非空、两两不重叠的半开整数矩形 `[左,下,右,上]`，其并集恰为本单待补格；不要求矩形数量最少。矩形按 `(下,左,上,右)` 排序输出。

矩形划分与输出顺序是确定的：只置换点表或方案中的数组、或重排对象键，不改变报告字节。

## 5. 算法与性能

网格可达 10^9 列 × 10^9 行（10^18 格），绝不逐格展开。禁入、通行矩形（合计 ≤25,000）与达标格（每点至多一格，≤20,000）是全部障碍；按所有矩形 x 边切出竖直基本条带，条带内每类覆盖是固定的 y 区间并，条带数与障碍数成正比而非网格面积。连通性在条带自由段上用并查集沿格边合并（条带内相邻、跨条带正长度重叠），工单范围由本分量待补条带按相同 y 区间横向合并而成。点归属用精确有理数 floor；面积全部用任意精度整数。

容量样例（复现：`python3 examples/resurvey_benchmark.py`，生成输入与独立验算不计时）：10^9 列 × 10^9 行、合法空 view，中线列 K=500,000,000 除第 K 行一格为免测通道外全部禁入，另有 20,000 个禁入单格 `(2i+2, 2i+2)`（i 取 0..19,999）。两次从输入文件到完整报告：

| 用例 | 结果 | CPU 时间 | 峰值 RSS |
| --- | --- | --- | --- |
| 中线缺口为通行 | 1 单，待补 `999999998999980000`（= 10^18−10^9−20,000），60,002 个矩形 | 0.36 s | 67 MiB |
| 中线缺口也禁入 | 2 单，待补 `499999999999980000`（= K·10^9−20,000）与 `499999999000000000`（= (10^9−K−1)·10^9） | 0.36 s | 67 MiB |

预算为每次命令 20 秒 CPU 时间、192 MiB 峰值 RSS；上表为本容器（CPython 3.11.2，Linux x86-64，单进程，无第三方运行依赖）实测，验算确认输出矩形在网格内、两两不重叠、不覆盖任何禁入格或通道、面积与对应单的精确格数一致。自动化测试 `tests/test_resurvey.py` 中的 `CapacityTests` 复现这两个用例并做同样的完整核对（不用抽样代替）。

## 6. 可运行示例

`./examples/resurvey.sh` 完整走查：`fixtures/build.json` 经 build → export → apply → view 导出三点 `[2,1,4]`（采集序号 10、20、30），再以 `fixtures/resurvey-plan.json`（4×4 单位网格、高程带 `[0,10)`、每格 3 批、`(3,0)` 免测通道、`(0,3)` 禁入）生成工单。三点同落 `(2,1)` 格使其达标已验收，报告开 1 单覆盖其余 13 个待补格（上节报告即该例输出）。

## 7. 边界

不重建三维点，不推断不同测次的点对应，不修改点表、方案或状态库；一个方案只处理一个区域，跨区批量派单由调用方逐区运行。矩形列表完全来自现场输入，命令不补充、不删减；工单只描述本轮补测范围，不调度人员或设备。
